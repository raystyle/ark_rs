# REQ-0008:包形专项批三

## Scenario

总台对齐回执差6：ark 现行三平台裸二进制、release 不挂边车；build-release 标准 rust 形单顶层目录包（二进制加 README 加 LICENSE，win 形 zip 他形 tar.gz）逐包 .sha256 挂 release，且标准播种白名单只收包形与边车（native 形特记点名裸件静默漏灌）。总台核准批三立项，收差6（包形迁移）与差10（AGENTS 补 dev 加 stable 双通道开放口径）。

## 对线裁定：总台开球回球与合流令

- **包形**：rust 标准形单顶层目录（直放二进制加 README 加 LICENSE，win zip 他 tar.gz）加逐件 .sha256 边车
- **包内目录名**：`ark-<target>` 无版本段（hst 族形实证一致；解包侧拼名定位免 glob；版本由 tag、边车、catalog pin 承载，路径不重复承载；标准模板名形为拷改面非硬契约，记入对线档）
- **双资产窗口与退役**：下版起两版 release 裸件与包形并挂（存量 selfupdate 加五端兼容）；第三版退役裸件，退役绑硬判据 = 五端 installed 全量达窗口一版以上、不满足自动延一版；窗口读序包形主名优先裸件回退臂，退役删臂
- **catalog 面**：切窗时总台改 [tools.ark] asset_pattern 与 extract 形（ark-self 到包形），ark 发布知会即切
- **selfupdate**：判新不动（digest 与边车锚）、下载腿按资产名族识别新旧、D46 回退名窗口保留
- **五端灰度**：wsl 先行后四端加 drift 观测窗
- **窗口算术**：2.2.0 裸件单形终版先行（批三不阻封版 wave），包形窗从下版起算

## 设计决策：动工面随窗一版实现与评审

- **release.ps1 开关形**：包形构建挂显式开关（如 `-IncludePackages`），缺省裸件单形：2.2.0 终版用缺省、窗口一版起开；避免代码先行落地污染裸件终版
- **seed 面 phase 无关**：`--ark-published` 裸件三名恒必到（齐备闸名单不变），包形名到则灌、无则跳（missing_ok 面），逐名核对覆盖实灌集：无需旗标与版本阈值
- **判新面设计注意（待窗一版对线确认）**：包形下边车与官方 API digest 是归档 sha 而非内层二进制 sha，现行「本机 exe sha 对 asset digest」等值判 current 的机制在包形失真；拟改包形资产按版本等值判 current（catalog pin 版本或官方 latest tag 对本机版本），归档 sha 只作下载锚校验：与总台「判新不动」的口径差异在归档哈希与二进制哈希之别，实现前随窗一版回执呈报确认

## 退役清理清单：第三版窗口执行八件

1. release 面裸件停挂，只出包形加逐件 .sha256 边车；release.ps1 打包步换包形（单顶层目录直放二进制加 README 加 LICENSE，win zip 他 tar.gz）
2. seed.py ARK_ASSETS 族与 r2-seed 资产齐备闸名单同步切包形名
3. stable 与 dev 段 sync 自然清裸件（源即段终态，无需专门清段批）
4. selfupdate 裸名主臂与 D46 三层回退名（msvc 与 ome 兼容名）整体退役；存量 msvc 二进制按 D46 原裁定走 omc catalog 通道重装
5. msvc stable 段排除清单退役与裸件退役同向两事，清段动作合并裸件退役批一轮走（stable 段窗口期由排除清单继续保空集防御）
6. catalog 总台侧 [tools.ark] asset_pattern 与 extract 切窗联动；本仓 catalog 副本四重门消费面不动（schema 兼容）
7. 历史版本段 ark/<旧版本>/ immutable 保留不动；ark.ohmygh.com 域面资产随 release 自动跟随
8. 五端灰度 wsl 先行后四端，每端收口判据 = self update --stable 至新版加 status 三态绿加 digest 与边车锚对账
