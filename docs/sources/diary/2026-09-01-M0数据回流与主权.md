# 2026-09-01 M0 数据回流与主权

> psd1 Pos 侧一次性回流、pin 平台分列、转换器只校验不再生：ome 从「psd1 的影子」变为数据主权方。

## 做了什么

1. **摸底推翻一个假设**：被吞的 linux 字段不在本仓 git 历史里（全历史树 grep 零命中）：2026-08-31 WSL 批次只提交了 src，tools.toml 的 linux 字段留在旧 clone 工作树随清理丢失，psd1 Pos 侧确为唯一现存数据源（TODO 判断得到实证）。本机 `~/ohmypwsh` 是无 .git 陈旧副本（缺 catalog.psd1），另 clone 到 `~/ohmypwsh-src`。
2. **一次性回流**（/tmp/backflow-m0.ps1，规则入 diary 不归档）：psd1 Pos 侧 19 在管工具 + go/zig/shellcheck 补录共 22 工具的 linux 静态族与 linux pin 四键；16 工具 mac pin（AssetMac/Sha256Mac）；绿装布局只给 oracle 可考的单二进制工具（download-mac-tools.ps1 清单 + 本机布局），目录型运行时（pwsh/rmux/zig/go）与 vault（cdn pattern 缺口）只回流 pin+pattern 留 M1 后续。psd1 钉版本的 pattern 解开为 `[0-9.]+`（ome 房风，否则 update 永远匹配不上）：踩坑：psd1 pattern 里版本是已转义形态（`7\.6\.5`），正则定位需按该形态双重转义；gh sums 又是未转义形态，两形态都要试。
3. **pin 平台分列 runtime**：Tool 增 8 平台 pin 字段与 `pin_tag/pin_version/pin_asset/pin_sha256` 访问器（无跨平台回退：平台无 pin 即未锁定）；`write_pin/write_sha256` 按平台键回写；resolve/checksum/install/status/main 全链消费点切平台访问器；toolver 补 go/zig/shellcheck 版本正则。黄金 pin 启用平台双 oracle（pin.macos.txt 实机冻结、pin.linux.txt 依夹具推导待 WSL 复核）：common 基建的「双 oracle 预留」注释派上用场。
4. **转换器只校验不再生**：import-catalog.ps1 重写为一致性校验器（托管 26 节静态字段对 psd1+New-ToolDef：冲突报错、ome 增补放行、缺失报错；平台族完整性：Pos 侧有数据则平台键不得缺；pin 值不校验）。首跑即抓到 jq sums 增补（M1 时我加的），据此定「增补放行」语义：psd1 是下限不是上限。mac 适配：数据源自动探测 `~/ohmypwsh-src`、`$env:TEMP` 换 `GetTempPath()`。
5. **kimi 剔除**（用户裁决：ohmyenv 不管 agent）：补录名单 go/zig/shellcheck/kimi 收敛为前三，校验器排除名单加 kimi，工具总数 31。
6. **同步纪律定案**（R001 四、6）：仓库 tools.toml 唯一源；self-deploy 即同步；部署态副本的 pin 回写视为缓存漂移，须回仓库提交再 self-deploy 收敛。

## 自省

- **数据工程先问「历史里有没有」**：`git log -S` 搜 src 字段名会命中结构体定义，搜数据文件必须带路径过滤或全历史树 grep：第一次搜索被 src 噪音误导，差点下错结论。
- **主权边界的双向语义**：校验器首跑抓到「ome 增补」时，第一反应是改数据迁就 psd1；正确方向是定义清楚谁是源：M0 之后 ome 是源，psd1 是下限，增补合法、冲突才报错。
- psd1 数据质量参差（转义/未转义混用、pattern 钉版本、Category 体系与 ome 不同）：回流脚本全部做了显式变换并留在 diary，不神话源数据。
