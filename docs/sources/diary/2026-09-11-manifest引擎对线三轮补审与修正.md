# 2026-09-11 manifest 引擎对线三轮补审与修正

## 起因

- claude 侧自省：manifest 引擎这批（`fc196b8..2b75a86` 两笔，11 文件加 530 行）没先过 codex 对线就推了，用户点名补审；本轮按五面逐条攻（L2 管道面、shims 硬链接与 cmd 兜底、manifest 拉取失败语义、install 双轨判定粒度、测试自适应与 POSIX 链接面）。
- 定位口径：先读 R016 v0.2 标准与 R001 契约，再读实现与夹具；能实证的不靠推理（管道面与 cmd 内容都在本机跑通后才下结论）。

## 逐条结论

- **L2 管道面（真缺陷）**：`run_post_install` 建了 stdout/stderr 管道却只在失败后才读，输出超管道缓冲（约 64KB）时子进程写端阻塞、永不退出，父进程轮询耗尽 300s 窗口后 kill 并误报超时。本机实证：同一 `cmd /c` 循环命令（约 1.2MB 输出）在「只轮询不抽干」形态下 10s 仍不退出，加抽干线程后 0.76s 正常退出。修正：两路管道并发抽干（滚动只留最近 64KiB 尾窗，抽干不吃内存），尾窗回传设 2s 上限（后台孙进程持写端时不无限等），超时路径补 `wait` 回收；公开入口套 300s，单测走可注入超时版。
- **shims 兜底内容（真缺陷，轻）**：`.cmd` 兜底原写嵌绝对路径并自做 `\\` 转义（cmd 不需要转义反斜杠，且绝对路径不可重定位）。本机实测：双反斜杠形态虽能跑通，但属无意义转换。修正：改纯函数 `shim_cmd_content`，内容 `@"%~dp0{源}.exe" %*`，与既有 `bunx_cmd_content` 同形（`%~dp0` 相对定位、目录含空格靠引号兜住、路径不入内容）。附纯函数单测（断言不含反斜杠与 BOM）。跨卷不成立（源与别名同目录必同卷），真门槛是 NTFS（exFAT 上硬链接失败自动回落 `.cmd`）。
- **manifest 拉取语义（真缺陷两处）**：一是 `let _ = sync_manifest_if_present(...)` 把失败全吞了（与注释宣称的「失败只告警」不符，验签不过时用户零感知）；二是调用点在「catalog 同锚早退」之后，`--force` 同步与 catalog 未变的日常同步都不会拉 manifest，omc 单方面上线 manifest 后台端永远拿不到（走内建回退漂移面）。修正：调用点提到早退之前、失败改 `[WARN]` 保留本地版本；404 提示改口径（未上线或网络未通）。仍待共识：`auto_refresh` 不拉 manifest，撤内建前必须补新鲜度门。
- **双轨判定粒度（真缺陷一处）**：shims 判定原按「节是否存在」而非「原语是否声明」，节存在但无 shims 键时会吞掉 bun 内建回退。修正：按原语判定（`ms.shims.is_some()` 才走数据面，否则回退内建）。另修 shim 落点：原传工具根 `install_dir`，在 POSIX 嵌套布局（python/go/codex/zig/rmux 的 dir 与 bin 不同）与 official 型下与 PATH 注册面不一致，改传 exe 父目录。`env_set` 保持逐原语回退（节只声明 shims 时遥测键仍走内建，非语义混搭而是规则），已在 R016 写明粒度与 parity 前提。
- **catalog 的 manifest 字段（漂移）**：字段值（节键）原被引擎与 lint 双双忽略（lint 拿工具名当节键）。修正：引擎与 lint 同解析（值给键、缺省同名节），并补引用不一致红灯用例。
- **测试面**：原 5 单测里失败路径只覆盖「命令不存在」（启动失败），非零退出码加尾行报告与超时杀进程两条路径无覆盖；shims 用例不区分链接与拷贝；夹具 catalog 无 `manifest` 字段故引用一致性分支空跑。修正：加平台自适应助手 `pi_for`，增补大输出不阻塞、失败尾行退出码、超时杀进程、`.cmd` 内容纯函数、shims 非拷贝（改源即见新值）与 POSIX `read_link` 断言、引用不一致红灯（临时目录自造），共 8 单测加 4 lint。

## 五轮快审共识余项三件

- ①自刷新跟进复验（本机真机）：manifest mtime 触旧 48h 后跑 `ome status`（走 fresh 早退路径），输出 `[OK] manifest 已同步（schema 校验与验签通过）` 且 mtime 刷新到当下；`OME_OFFLINE=1` 再触旧则 mtime 不动（自动路径整条关）。语义自洽：mtime 即上次成功落位时刻，显式 sync 落位也刷新，故显式拉一次即自动续期；`catalog status` 的 age 与 synced 两键正好区分「锚同但本地旧」与「锚已漂」。
- ④顺序坑（抓出并修）：`kill` 加 `wait` 之后再 `taskkill /PID x /T /F` 打印 `ERROR: The process "x" not found.`，孙进程照活；本机 A/B 实证 taskkill 先行才 SUCCESS 三连清树。改为先 taskkill 再 kill 加 wait，超时用例补「无残留 ping」断言。**测试自身也踩了一脚**：首版断言大小写敏感，而 tasklist 输出 `PING.EXE`，旧顺序下照样绿（假绿）；改大小写不敏感后把旧顺序临时放回反向验证，用例如期红，判别力确认。教训：断言拿真实输出样例核大小写与格式，光看绿不算过。
- ③接口面留痕（未改码，记给数据面与后续裁）：post_install 失败降 stderr WARN 后，机器可读面（stdout 行）看不到失败，R013 冻结面 `install` 行没有 post_install 维度；幂等分支每次 install 都重跑命令，故已在 R016 L2 补「命令须幂等」的数据面约束。另记两处观察：自动路径三处补拉的结果均 `let _ =` 吞掉（失败无痕，与 M019 同型，建议至少 WARN 或在 install 时装前对过期 manifest 也告警）；manifest 本地加载未做签名巡检（catalog 有），手改本地 manifest 会被 install 直接执行，可在加载处对齐 catalog 口径。

## 六轮快审共识②应用点上提

- 抓出三件：一，**env_set 在 uv-git/npm-tgz 首次装仍被跳过**（新 helper 只搬了 shims 与 post_install，`ensure_user_env_overrides` 只挂主链两处，两通道早退拿不到，重装走幂等分支才补）；二，同一段原语逻辑**三份并行**且语义已分叉（主链两份 shims/post_install 失败硬错，新 helper 降 WARN）；三，`clippy` 报两处 8/7 超参（为传 manifest 给通道函数加参），说明「clippy 干净」是在最后改动之前跑的。
- 修法：原语应用点收成唯一实现 `apply_manifest_primitives`（env_set 加 shims 加 post_install；L1 硬错、L2 降 WARN），主链幂等分支与成功尾、两早退通道共用；通道侧调用点放在 `install_tool` 调用处（通道签名不增参，超参警告自然消失）；shims 落点加「非绝对路径即跳过加 WARN」防线（`Path::new("bh").parent()` 是空串，裸名 exe 会退化成按 CWD 拼相对别名）。落 M022。
- ①的实证（本机真机）：npm 全局 bin 在 fnm multishell 下是**每 shell 一个** `AppData\Local\fnm_multishells\<pid>_<ts>` 目录（本机积了 6556 个），里面 `bh`/`bh.cmd`/`bh.ps1` 齐全但**无 .exe**；WSL 侧是 `~/.local/share/fnm/node-versions/v24.20.0/installation`（随 node 版本变）。故 npm-tgz 的 shims 落点不具跨会话保证（Windows 更因引擎按 `{source}.exe` 查源而无实际效果，等于 POSIX-only），已在 R016 落注，结论是 npm 族别名交包自身 bin map。②的核验：uv-git 通道**当前无在役条目**（seed 零 `extract = "uv-git"`，rmux 实为 `extract = "rmux"`），且其 exe 为 `%LOCALAPPDATA%\...` 变量路径（非 PATH 现查），故「装完 PATH 未刷新」不成立；若将来有裸名 exe 的 uv-git 条目，新加的绝对路径防线兜住。③的语义：单次命令内只跑一次（幂等分支与通道互斥），跨命令重跑即重试路径，与主链一致。

## 七轮快审 POSIX 用户 bin 直链兜底

- 这项本身对症（lan-linux 的 hostExec 不加载 profile，注册的 PATH 目录形同虚设；`~/.local/bin` 才是非交互可达的 XDG 基建），但幂等判据有洞：只看 `dst.exists()`（跟随链接），**有效但指向旧 target 的链接会永久留着**，版本目录型布局（zig 的 `~/zig/zig-...-0.16.0`）升级换目录后直链仍指旧版且旧目录通常在，悬空分支永不触发，PATH 顺序在前即陈旧遮蔽。已改为比对 `read_link == exe`：已指对跳过、指向别处（含悬空）先删再建、落点是真文件（用户自装）绝不动、exe 本就落该目录时不建自指链接；语义抽成 `link_into_user_bin` 并补六态用例（WSL 首验通过）。落 M023。
- 效度边界实测（纠正注释里的过度断言）：WSL `env -i /bin/bash` 的最小 PATH 是 `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`，**不含 ~/.local/bin**；交互/宿主 PATH 才含。故兜底有效的前提是宿主 PATH 含该目录（omc hostExec 属于这一类），已在 R016 写明「兜底不等于把 PATH 送进去」。
- ② agent 纳管口径核了实况：WSL 上 codex/claude/grok 都在 `/home/ray/.local/bin/*`（本身就是直链落点，故 `exe == dst` 早退，口径成立），Windows 侧走注册表 PATH（进程级持久，无 profile 问题，stub 合理）。潜在洞只在「agent 装在厂商目录且靠 profile 注入」的布局：那时 same-name 直链才有价值，属口径待裁（未改码）。
- 顺手一件仓库卫生：`.tools/tmp_fix.py`（这次改动的行内改写脚本）进了仓，一次性脚本不该入仓，且违 .tools 的命名、PEP 723 头、README 清单登记三规，正是 M018/M020 同型隐患（`newline='\n'` 重写整文件正是 EOL 假 diff 的成因）。已删。

## 八轮快审 S017 npm 型 fnm 解析

- 字典序取版本（同型二犯）：`fnm_node_bin` 无 `aliases/default` 时按字符串序取最高版本目录，`v9.9.9` 会压过 `v24.20.0`（本机字符串序实测 True），会选错 node。仓里早有 `resolve.rs` 的 `semver_取最大_数值段比较而非字典序` 用例与注释，新代码没复用。已把 `semver_cmp` 提 `pub(crate)`、新增容前导 v 的 `version_key`，解析核抽 `fnm_node_bin_in(base)` 加用例（别名优先、无别名取含 npm 的数值最大、无 npm 版本跳过、v99 无 npm 不夺标）。落 M025，并记 G004 待办：同型三犯前把「版本比较」收敛成单一入口进 references。
- `set_var` 副作用面（回答原问）：只在 `which npm` 失败时注入，且**同时**给子进程 `PATH` 环境变量与自身进程（后者为让装后 `exe_path` 的 PATH 现查与探测同链生效）。单命令进程内可接受：本仓 install 循环单线程、`ome install all` 也只是把合法的 node bin 留在 PATH 里；真正要防的是**测试进程**（多线程下改 env 有竞态），而集成测试都是 spawn 子进程，故无实际风险。唯一要记的是它让进程 PATH 与用户 shell PATH 不再一致，输出里别用它反推用户环境。
- 隔离开关只守一面（已补全）：`OME_TEST_NO_PATH_REG` 原来只管 `add_user_path`，而用户面写入另有三个门（`set_user_env_var`、`ensure_profile_hook`、`ensure_user_bin_link`）。今天测试恰好不碰后三面（POSIX 侧 HOME 已沙盒、Windows 侧装的多是 skip 路径），但 Linux CI 上真装一次嵌套布局工具就会写进 runner 的真实 HOME。已收成 `platform::user_env_write_blocked` 单一判据，四处共守。
- `ensure_profile_hook` 的 `>>>`到`<<<` 生成法：marker 传 `# >>> ome fnm >>>`，`replace(">>>","<<<")` 得闭标记，与 `merge_env_exports` 只动自己 `# >>> ome env` 块互不擦除（实测保留），逻辑成立；但幂等判据是「全文含该行」而非「块在位」，同功能不同写法的重复钩子会追加第二个块，可接受，建议后续按块判定。另建议钩子加 `command -v fnm` 守卫（fnm 不在 PATH 时 profile 会报错）。

## 九轮快审 S017 O6 静态位锚定

- O6 方向对（交互 shell 的 fnm hook 把会话级 multishell 目录前置 PATH，直链锚上去注销即悬空），但「静态位无条件优先」把口径推过头：装了 fnm 却默认用 Homebrew/system node 的机器，ome 会把 npm 包装进 fnm 的版本目录；macOS 上 `~/.local/bin` 常不在 PATH，于是**装成功却在 shell 里不可见**（只靠直链兜着）。已改成条件优先：`which npm` 命中的若是会话级 shim 才让静态位插队，命中真安装则维持 PATH 优先（不抢用户既定生态）；判据抽 `is_session_shim`（认 `fnm_multishells` 路径段，跨平台纯函数）并补用例含 Windows 反斜杠形态与 homebrew 反例。
- 回退序（回答原问）：静态位不可用时回落 PATH 现查（哪怕是会话 shim，先能装），都没有才回落裸名由调用方报「先 ome install fnm」，可接受；修的是 fnm 损坏时不该断路。另补 `aliases/default` 分支必须目标版本真含 npm，否则落回版本扫描（残缺默认别名不再断路），并加用例。
- 会话级路径的寿命教训再确认：锚定动作（直链、PATH 注入目标、缓存键）都要问「这个路径活多久」；本轮把「锚定只锚静态位」写进 R016。

## 十轮快审 D40 seq 回滚门

- 抓出的洞：seq 门只挂在显式 `sync_to` 与自举，**默认自动路径 `auto_refresh` 没挂门也没记已见基线**，而它才是日常每条命令都走的那条（TTL 过期即触发）。本机同状态 A/B 实证：旧行为接受「已见 99 vs 云端 2」的回滚内容并打印 `[OK] catalog 已刷新`（内容被替换成回滚件），新行为 `[WARN] tools.toml 回滚重放拒收`、本地内容 sha 逐字不变、并打退避标记免每命令重探。教训一般化：**加防护门先枚举全部落位/写入点**（`rg "place\("` 就是清单），且「过门」与「记基线」必须成对出现在每条接受内容的链上，只过门不记基线，窗口恒开（记录停在 0，任何回滚都「不低于已见」）。落 M026。
- 补齐三处：`auto_refresh` 更新分支过门加落位后记 seq、同锚分支把在位件 seq 补记成基线（升级到 seq 感知引擎后的首刷自愈）、`bootstrap_catalog` 无基线可比（鸡生蛋：没有本地件就无从比较）但也把拉到的 seq 记成基线。另把 `seq_gate` 出路提示里的 `.{what}.*.seq` 改成实际文件名 `.{what}.seq`（原写法像 glob，用户照着删会犹豫）。
- 测试面：`seq_gate`/`toplevel_seq`/已见记录读写此前零用例，补六态（缺/负/非整数视 0、低拒含出路、等过、高过、坏记录按 0、在位件补记、无 seq 不建记录）。真机收尾态：`.tools.toml.seq=2`、本地件 sha 与云端锚逐字一致。
- 顺带核出**omc 数据侧的真错**（本轮实测撞上，非本仓）：云端 manifest 新增的 `[manifest.fnm.post_install]` 写成扁平数组 `win = ["fnm","install","24.20.0","--default"]`，契约要求数组的数组 到 引擎反序列化整份失败、WARN 保留本地版本（行为正确但影响面是全部节：pwsh/dotnet env_set 与 bun shims 一并不生效），fnm 的 node 供给因此实际没落端。已把「类型即契约 + 单节畸形整体拒载」写进 R016，并请 omc 让 manifest-lint 加 schema/类型面（引擎解析器即参考实现）。
