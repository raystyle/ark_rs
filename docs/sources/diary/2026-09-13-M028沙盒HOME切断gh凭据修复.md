# 2026-09-13 M028 沙盒 HOME 切断 gh 凭据修复

## 起因

- 覆盖度实弹：WSL 总台跑 `ark cargo test`，`tests/linux_install.rs` 两用例（`linux_profile_path_幂等`、`linux_jq_安装部署状态闭环`）FAILED，报 `gh api 失败（4）: To get started with GitHub CLI, please run gh auth login`。总台 gh 已认证（raystyle 登录在 `~/.config/gh/hosts.yml`），但测试用 HOME=临时目录隔离装位环境。
- 定位：`--latest` 解析链在 api.github.com 直连失败（403/网络）时回退 `gh api`（resolve.rs 认证兜底通道）；gh 凭据查找序 GH_CONFIG_DIR > XDG_CONFIG_HOME > `$HOME/.config/gh`，沙盒 HOME 把已登录的文件凭据一并隔离。ark 侧 env token（GH_TOKEN/GITHUB_TOKEN）两通道均已原生认且随子进程继承（直连 Authorization 头与 gh 子进程 env 都覆盖），缺的只是文件凭据，故修在测试夹具层，生产代码不越 HOME 找配置。

## 修法

- `tests/linux_install.rs` 增 `relay_gh_credentials`：GH_TOKEN/GITHUB_TOKEN/GH_CONFIG_DIR/XDG_CONFIG_HOME 任一在位即跳过（env 凭据随继承、配置已指真实位）；否则真实 HOME 的 `~/.config/gh/hosts.yml` 在位时给子进程注 `GH_CONFIG_DIR` 指向真实 gh 配置，凭据零落盘、不碰沙盒隔离；CI 无登录静默跳过。
- 首版是 hosts.yml 复制进沙盒 HOME，codex 对线**阻断**：副本以 0644 落在 0755 临时目录，token 同机可读；按其推荐改 GH_CONFIG_DIR 注入，复制路径整体删除。
- R004 增「凭据转继」行、M028 错条归 M101、INDEX M101 行同步。

## codex 对线

- 首轮一条阻断（凭据落盘可同机读）加两条 nit（GH_CONFIG_DIR 漏进跳过列表；转继对不需要网络的用例也触发）。阻断按推荐修法收编后回执确认「阻断已消」；GH_CONFIG_DIR nit 随修法自然消；触发面 nit 随注入式零成本化不再有意义。
- 旁注留档（既有、非本 diff）：`selfupdate.rs:444` 直连只读 GH_TOKEN 不读 GITHUB_TOKEN，与 resolve.rs 不对称，gh 兜底通道能盖住故无实际影响，后续顺手对齐。
- 残余边界（双方认可不必动）：gh 凭据在 keyring 或 GHE 特例的机器上守卫不注入，与修复前同态。

## 纪律

- 教训入 M028：沙盒隔离只该隔「写入面」（HOME、PATH、注册表），网络凭据这类「读取面」必须显式转继；且转继优先注入（GH_CONFIG_DIR 一类指路 env）而非复制凭据本体，复制必然引入落盘权限面。
