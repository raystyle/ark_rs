# 2026-09-13 仓再更名 ark_rs 对齐

## 起因

- 推送六笔修复系列时 GitHub 返回 repository moved：仓已由 `raystyle/ark-rs` 再更名 `raystyle/ark_rs`（推送靠 301 成功）。`gh repo view raystyle/ark_rs` 实证在位、描述完好（昨日经重定向已落对仓）；用户来件一直写 `ark_rs`，我此前按旧 remote「纠正」为 ark-rs 是错的。
- 对齐面清点：`git remote`、`src\selfupdate.rs` 的 `REPO` 常量（B1 起自更新通道、doctor 三探针、镜像 URL 全由它单源派生）、`.tools\seed.py` 仓引用、活文档（README、AGENTS、SKILL、PLAN 仓库名行）；历史日期行（ROADMAP/GOAL/PRD/diary）按史实保留。

## codex 对线

- 一条阻断（已按处方逐字收编）：README 只换了 clone URL，两处 `cd ark-rs` 漏换，照抄快速上手即失败。顺手 nit 已做：CHANGELOG Unreleased 补记、本机 WSL 第二克隆（`~/ark_rs`）remote 同步切新名。
- 兼容读裁定（通过）：REPO 是出站 URL，客户端是 git/GitHub 而非 ark 自己，与 D41 环境变量读回不同层级，无需引擎侧读回。实测三链：api 301 跳仓库 id 规范址、github.com 301 到新名、gh api 走重定向且同 host 保认证。
- 机制细节留档（nit，接受）：ureq 2.12 默认重定向策略 Authorization Never，旧二进制直连 301 后丢 Bearer 回落匿名配额（公开仓仍 200），gh 回退与镜像段兜底不断源；镜像段与资产名（`ark/`、`ome/`、`ark-*`、`ome-*`）与仓名解耦，更名不动。
- seed.py 裁定（通过）：download_asset 只拼 release 下载 URL 走 urllib（自动跟 301），不碰 API 不带 token；该链本机无覆盖，下次发版即首验。
- 残余观察（codex 前轮截断提及）：本机自更新注册键仍指 `D:\ohmyenv-rs` 旧位，按 PLAN 检查单该在下次发版自更新时重建一次，记此待办。

## 验证

- [实证] `cargo test --lib selfupdate` 7 绿（含 mirror_fallback 相关）、`--lib doctor` 8 绿（同源机检随 REPO 派生全过）、`cargo clippy --lib --tests` 干净；门禁四件套绿后提交。
- [实证] `gh repo view raystyle/ark_rs`：public、描述一字不差；旧名 view 返回同仓。

## 纪律

- push 输出里的 remote 提示（moved/redirect/deprecated）是免费的对齐信号，出现即查即对齐，不能靠重定向长期续命（重定向在他人抢注旧名或 GitHub 政策变更时断裂）。
