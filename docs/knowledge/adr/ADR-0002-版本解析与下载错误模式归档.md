# ADR-0002 版本解析与下载错误模式归档

## Context

版本解析与下载链的行级错误史（REST、cdn、网络、哈希）（原 mistakes 分类文件 M101-版本解析与下载-错误.md，ADR-0001 批四并入）。D 前时代至 2026-09 的 M007/M008/M013/M019/M026/M028 六类错误模式。错误史封存不改写，同根因聚合条目保留最早编号。

## Decision

错误模式与正解纪律以本 ADR 附录表为唯一权威；新踩坑当场记 diary，构成纪律变更的立新 ADR（M0xx 行级编号制度随本批退役）。

## Consequences

- 查错误模式从 `docs/knowledge/adr/README.md` 入（编号 M0xx 在附录表内仍可检索）。
- 历史 diary 中 M0xx 引用为当时事实记录，不改写。
- 附录原表封存：新错误不再接编 M0xx，以 diary 与新 ADR 承载。

| M007 | 2026-09-07 | 已修正 | `ome update` / `install --latest` 对 uv/jq/bun 等资产名跨版本不变的工具报 sha256 校验失败；或 install --latest 把新 sha 写进旧 pin 四元组 | `expected_sha256` 只比 pin asset 名不比 tag；`sha_backfilled` 在跨 tag 时仍 `write_sha256` | 同 tag 且同 asset 才用 pin sha，否则走官方 sums；跨发行 sha 只随 `update_lock` 与 pin 一起写 |
| M008 | 2026-09-07 | 已修正 | 下载失败后缓存里留下半截文件，无 sha 基准时下次直接复用并解压或执行 | `download_once` 对 dest `File::create` 后 copy 失败仍留下 dest；无 sha 分支无条件复用 | 先写 `<asset>.part` 再 rename；空文件视为未完成不复用；curl 同样写 part |
| M013 | 2026-09-08 | 已修正 | M007 修复已在仓（5f66801）但 `ome update herdr` 仍报旧 pin sha 校验新包失败，疑似修复无效 | 部署 ome 二进制（09-07 17:15 构建）早于修复提交（19:29），滞后二进制缺同 tag 防护 | 复现已修行为前先 `ome self update` 对齐部署二进制与源码，再验证（herdr 0.9.0 升级实证：自升级后防护即生效） |
| M019 | 2026-09-11 | 已修正（2026-09-11） | `ome catalog sync` 永远拉不到云端 manifest，本机与 CI 都不报错，只打印一句「云端 manifest 不可得（未上线）」像是云端没上线 | `sync_manifest_if_present` 三处 URL 写成 `format!("https://{MIRROR_BASE}/...")`，而 `MIRROR_BASE` 常量本身已含 `https://`（实际请求 `https://https://env.ohmygh.com/...`）；更坏的是取锚失败分支把「真 404」与「URL 拼错、网络失败」归成同一个静默跳过，拼错被当成未上线掩盖 | 拼 URL 一律 `format!("{MIRROR_BASE}/...")`（与 `cloud_catalog_url` 同形，锚常量自带 scheme）；静默只留给真 404，其余失败必须落告警（同轮已把 `let _ =` 吞错改 WARN）；联网路径的 bug 离线单测兜不住，必须一次真网拉取或探活实证 |
| M026 | 2026-09-11 | 已修正（2026-09-11） | D40 seq 门只挂在显式 `sync` 与自举路径，**默认自动刷新路径（`auto_refresh`，TTL 过期后每条命令都走）没挂门也没记已见 seq**：本机实证同状态下一版接受「已见 99 vs 云端 2」的回滚内容并打印「[OK] catalog 已刷新」，另一版正确拒收 | 新增防护时按「我改的那条链」挂门，没按「所有落位点」枚举：`place(` 在文件里有三处（sync_to、auto_refresh、bootstrap），只覆盖了两处；同理已见基线只在显式路径写，默认路径跑一年记录仍是 0（等于门形同虚设） | 加防护门先枚举全部落位/写入点（`rg "place\("` 一类清单）逐点接线；「记基线」与「过门」必须成对出现在每条接受内容的链上（只过门不记基线等于窗口恒开）；回归测试要覆盖默认路径而非只测显式入口 |
| M028 | 2026-09-13 | 已修正 | 覆盖度实弹：WSL 总台跑 `cargo test`，`tests/linux_install.rs` 两用例（linux_profile_path_幂等、linux_jq_安装部署状态闭环）FAILED，报 `gh api 失败（4）: To get started with GitHub CLI, please run gh auth login`；总台 gh 明明已认证（hosts.yml 在真实 `~/.config/gh`） | 用例以 HOME=临时目录隔离装位环境，gh 凭据查找序 GH_CONFIG_DIR > XDG_CONFIG_HOME > `$HOME/.config/gh`；沙盒 HOME 把已登录的文件凭据一并隔离，api.github.com 直连一失败（403/网络）就落进无凭据的 gh api 回退通道。ark 侧 env token 两通道均已原生认且随子进程继承，缺的只是文件凭据 | 测试侧凭据转继 `relay_gh_credentials`：env token 在位直接跳过，否则给子进程注 GH_CONFIG_DIR 指向真实 gh 配置（hosts.yml 在位才注），凭据零落盘（首版 hosts.yml 复制进沙盒被 codex 对线阻断：副本 0644 落在 0755 临时目录同机可读）；CI 无登录静默跳过。沙盒隔离只该隔「写入面」，网络凭据这类「读取面」要显式转继 |

## 范围注记

- 资产名含版本号的工具（如 `gh_2.x_windows_amd64.zip`）主要踩 M007 的 sha 回写污染；资产名不含版本的工具踩旧锚校验。
