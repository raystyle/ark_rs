> 本细则是 AGENTS 操作规则「写文档时」的细则载体。自 ohmyagents 同名细则平移（其源头为 `D:\ohmypwsh` 同名职责文件的裁剪版）。
> 2026-09-02 v2：全文吸收《中英文 Markdown 技术文档写作规范》v1.0（用户提供）为项目规范，含四类禁用字符硬禁令、豁免区、替代写法、空格混排与结构规则；机检工具 `mdcharlint.py` 进门禁。

## 一、文件命名标准

> 核心原则：看文件名就知道内容。文件名 = 博客式长标题，标点一律用 `-` 断句（不含空格、括号、冒号、顿号、点号，仅中文/字母/数字与 `-`）。

| 位置 | 命名模式 | 说明 |
| --- | --- | --- |
| 根目录 | `INDEX.md` | 文档总索引（编号即定位；唯一索引，不另设清单） |
| 根目录 | `GOAL.md` / `PLAN.md` / `TODO.md` | 任务目标管理 / 当前目标方案 / 进度清单 |
| 根目录 | `AGENTS.md` / `CHANGELOG.md` / `README.md` | 项目级文档（工具约定大写） |
| `docs\sources\proven\` | `PNNNN-动词短语.md` | 已完成状态的 plan 归档（P 加 4 位递增，不复用） |
| `docs\sources\diary\` | `YYYY-MM-DD-主题.md` | 项目日记（**一天一篇**；写当天全部工作的总结与自省，即概貌、关键裁决、得失；不写工作细节，细节进方案与研究） |
| `docs\knowledge\research\` | `SNNN-博客式长标题.md` | 研究原型过程（为什么；六态对齐）；写作规范见 `docs\operations\G002-研究标准细则-结构与六态标记.md` |
| `docs\knowledge\references\` | `RNNN-博客式长标题.md` | 开发测试参考（要做什么怎么做；规则完整内容、工作流程、经验教训的正面沉淀，六态溯源） |
| `docs\operations\` | `GNNN-博客式长标题.md` | 元规范（怎么写文档、怎么做研究、怎么推进工作流） |
| `docs\operations\` | `template.md` | 方案模板（不编号） |
| `docs\mistakes\` | `M1NN-主题短语-错误.md` | 错误速查分类文件（出错怎么纠；经验教训的反面沉淀，与 references 互补） |

规则细项：

- 禁止模糊词（`misc` / `other` / `temp` / `new`）
- 编号前缀全局唯一且不复用：`P`（proven，4 位）、`S`（research，3 位）、`R`（references，3 位）、`G`（guide，3 位）、`M`（mistakes：分类文件 M1xx，行级错误 M0xx 按首次踩时间递增）
- 新文档落位后登记 `INDEX.md` 对应节；编号接当前最大号
- 特殊名固定大写：`INDEX` / `GOAL` / `PLAN` / `TODO`；小写固定：`template`
- `docs\sources\proven\` 只放 `PNNNN` 方案；当天流水账不进 proven

## 二、四类禁用字符硬禁令

> 来源：《中英文 Markdown 技术文档写作规范》v1.0（2026-09-02 用户裁决转为项目规范）。目标：消除智能体写作痕迹（破折号、箭头、emoji 装饰），保证 lint 可过与终端渲染正常。豁免区之外一律禁止，每条可被 `mdcharlint.py` 机械判定。

### 2.1 破折号与连接号

禁止：`—`（em dash）、`——`（中文破折号）、`–`（en dash）、`―`、`−`（正文负号）、`ー`（长音符）。连字符 `-` 合法（复合词、CLI 参数、编号范围）。

| 语义 | 违规写法 | 合规写法 |
| --- | --- | --- |
| 补充说明 | `该功能支持三种模式——快速、标准、深度` | 该功能支持三种模式：快速、标准、深度 |
| 插入解释 | `延迟——不含网络传输——低于 50 毫秒` | 延迟（不含网络传输）低于 50 毫秒 |
| 数值范围 | `3——5 天` | 3 至 5 天 |

### 2.2 箭头

禁止 U+2190 至 U+21FF 全区及装饰箭头（`→` `⇒` `⇐` `←` `↔` `➜` 等，本行即规则定义区样张）。ASCII 组合 `->` 与 `=>` 仅限行内代码与代码块；mermaid 源码内 `-->` 合法。

| 语义 | 违规写法 | 合规写法 |
| --- | --- | --- |
| 流程步骤 | `请求失败 → 自动重试 → 上报日志` | 1. 请求失败后自动重试。2. 重试仍失败则上报日志。 |
| 映射关系 | `用户 ID → 订单列表` | 用户 ID 对应订单列表 |
| 转换动作 | `YAML → JSON` | 将 YAML 转换为 JSON |
| 状态迁移表格 | `待审核 → 已发布` | 拆为「起始状态」「目标状态」两列 |

### 2.3 emoji 与装饰符号

禁止现代 emoji（U+1F000 至 U+1FAFF）、杂项符号与装饰（U+2600 至 U+27BF）、变体选择符与零宽连接符、`‼` `⁉` `ℹ`。提示与警告用 GFM 警示块（`> [!TIP]`、`> [!WARNING]`、`> [!CAUTION]` 等，不支持时退化为加粗）；勾选与状态用「是 / 否」「支持 / 不支持」文字。

### 2.4 全角字符与智能引号

全角仅限中文正文标点白名单：`，。：；？！、（）《》「」『』·`（省略号 `……`）。全场景禁止：全角字母与数字、全角空格、智能引号 `“” ‘’`、全角符号混入代码（`＝ ＋ ％` 等）。中文引号统一直角 `「」`；英文与代码用直引号。代码、行内代码、URL、英文整句、数值与单位一律半角。

### 2.5 豁免区

围栏代码块（含 mermaid 与公式）、行内代码、链接与图片目标（URL 原文）、第三方引文原文（引用块内保持原样，不得「修复」）、规则定义区（黑名单表与违规示例列）。

## 三、空格、标点与结构

1. 中文与英文之间、中文与数字之间加一个半角空格（如在 LeanCloud 上创建对象、耗时 3 秒）；数字与单位之间加空格（32 GB、100 ms），度与百分比例外（233°、15%）。
2. 全角标点与相邻字符之间不加空格；不重复使用标点（`！！` 禁止）。
3. 混排句子标点以主语言为准：中文句用全角，英文整句内部用半角。
4. 书籍与规范用《》；文件名与路径用行内代码；中文并列用顿号、英文用逗号并保留牛津逗号。
5. 列表项末尾：完整句子加句号，短语不加，同一列表内统一。
6. 标题：一级标题全文唯一、层级连续不跳级、句末不加标点、空标题禁止。
7. 列表：同层同一标记、嵌套不超三层、不用列表承载成段论述。
8. 代码块必须标注语言（无对应语言标 `text`）；表格表头用名词短语、单元格短句；链接锚文本描述目标内容（禁「点击这里」）；图片 alt 必填。
9. 术语：专有名词保留官方大小写（API、JSON、GitHub）；缩写首次出现给全称；同一概念全文同一译名。

## 四、写作分工与历史豁免

- **树形结构**（人工）：节点加子项，禁止整段混杂叙述。
- **标题干净**（人工 + 机检）：不带括号、不喊口号、不用破折号；解释放标题下一行引用 `>`。
- **事实性断言**（强制）：研究与测试文档的事实性断言必须标六态（实证 / 推断 / 经验 / 记忆 / 假设 / 直觉），标准见 `docs\operations\G002-研究标准细则-结构与六态标记.md`；不标或实证滥用即视为未完成。
- **历史归档豁免**：`docs\sources\diary\` 与 `docs\sources\proven\` 为历史记录不回改（`mdcharlint.py` 默认跳过，`--all` 可全量）；**新写作（含新增 diary 批次）一律合规**。
- **输出前自检**（智能体）：逐段回查四类禁用字符；确认命中均在豁免区；豁免区外执行替代写法；替换后重读确认语义无损。

## 五、检查与修正

| 检查 | 命令 |
| --- | --- |
| 全仓扫描 | `rumdl check .` |
| 禁用字符机检 | `uv run --script .tools\mdcharlint.py .`（默认跳过 diary/proven 历史归档；`--all` 全量） |
| 标题括号机检 | `uv run --script .tools\md-heading-scan.py` |
| 引用断链机检 | `uv run --script .tools\md-ref-scan.py` |
| 自动修正 | `rumdl check --fix .` |
| 纯格式化 | `rumdl fmt .` |

配置 `.rumdl.toml`：保留格式类；关闭行宽、首行 H1、块引用空行、强调代替标题。
